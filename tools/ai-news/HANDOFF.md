このツールは claude.ai 上のリモートコンテナで作られました。そのコンテナは
**外部ネットワークが遮断されており、Windowsでもなかった**ため、検証できていない前提がいくつか残っています。
ローカルで作業を引き継ぐ人（人間でもClaudeでも）は、まずここを読んでください。

## 何を作ったか

`tools/ai-news/` — AI関連のRSS/Atomを集約し、Obsidian vault に日次ノートを書き出すNode製CLI。
**外部npm依存はゼロ**（Node組み込み `fetch` のみ）。

想定環境:

| 項目 | 値 |
| --- | --- |
| OS | Windows |
| Obsidian vault | `C:\obsidian\vault` |
| 出力先 | `C:\obsidian\vault\03_AIニュース\{{date}} AIニュース.md` |
| ブランチ | `claude/ai-news-daily-obsidian-h1nvu6`（main未マージ） |

## 動かし方

```powershell
cd <repo>\tools\ai-news
copy config.windows.example.json ai-news.config.json
node bin\ai-news.js check      # フィード疎通確認
node bin\ai-news.js --dry-run  # 書き込まず内容確認
node bin\ai-news.js            # 本番
node --test test\*.test.js     # テスト（18件・ネットワーク不要）
```

## 変えないでほしい設計判断（変えるなら理由を添えて）

1. **外部依存ゼロ** — `npm install` 不要、サプライチェーンリスクなし。パーサを自前で持つ代償を承知で選んだ。
2. **LLM要約をしない** — RSSの概要文をそのまま整形する。書かれていないことは書かれない。
3. **原文リンクを必ず併記** — ノートは索引であって一次情報ではない。
4. **エンティティを `[[wikilink]]` 化** — ここがObsidianを使う理由そのもの。外すとRSSリーダーで十分になる。
5. **取得失敗をノート内に残す** — 静かに記事が減るのが最悪の壊れ方。

## Windowsで踏みやすい地雷（対策済みだが理由を記録しておく）

- **JSONのバックスラッシュ**: `"C:\obsidian\vault"` はJSON構文エラーになる。`/` 区切り推奨。
  `src/config.js` がパースエラー時にこのヒントを出す。
- **文字化け**: 既定のコードページだと日本語ログが化ける。`run-ai-news.cmd` が `chcp 65001` してから実行する。
- **状態ファイルの `rename` 失敗**: OneDrive等がファイルを掴むと失敗しうる。`src/state.js` が直接書き込みにフォールバックする。

## 既知の制限

- 要約はRSSの概要文そのまま。概要を出さないフィードでは見出しとリンクだけになる。
- 英語記事は英語のまま（翻訳なし）。
- 同一ニュースの英語版と日本語版は別記事として並ぶ（URLもタイトルも違うため）。
- **CLIが作るノートは「索引」であり、分析や日付の検証は付かない。** 2026-09-15 に手作業で作ったサンプルノートは
  Web検索で裏取りと分析を加えたもので、CLIの出力とは品質が異なる。同じものを期待しないこと。
